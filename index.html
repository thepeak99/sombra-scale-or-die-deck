Signatures — funds

Fixable

Encryption — privacy

Not fixable

  • Most of today’s privacy protocols seal with elliptic-curve key exchange — shielded today, decrypted tomorrow.

Precise about "post-quantum"

What's quantum-safe — and what isn’t yet.

Quantum-safe in Sombra

PQ
  • Note contents — ML-KEM-768 + AES-256-GCM (key via HKDF-SHA256). Harvested ciphertext stays sealed.
  • Ownership & spend proofs — hash-based STARKs over SHA-256 commitments.
  • No signature to spend — authority is knowledge of your key, proven in zero knowledge.
  • All calls to our infra — remote prover, indexer, QFire (our RPC). ML-DSA-65 (FIPS 204) signed: an extra PQ layer on already-safe traffic.
  • Remote prover in enclaves — attestation lets you verify the code that proves.

Still classical — Solana layer

Ed25519
  • Settlement & consensus on Solana.
  • Transaction signing & fee payers.
  • Prover-node voting keys — rotated after every use to limit exposure.

Our rule: if the authorization path is Ed25519, we don’t call it post-quantum.

Crypto agility

PQC where it’s urgent. No signatures where they’re hard to swap.

Encryption — the urgent half

Harvest risk
  • Ciphertext faces harvest-now-decrypt-later — so PQC now (NIST IR 8547 calls this the urgent half).
  • The KEM lives outside the proof — swapping it is a wallet upgrade, not a new circuit.
  • Every envelope is versioned; NIST’s non-lattice backup, HQC, is a named swap path.

Signatures — nothing to chase

PQ
  • Spend authority uses no signature — nothing address-bound to migrate.
  • Still classical: Solana settlement (Ed25519) — it migrates with the chain.
Sources — NIST IR 8547 (post-quantum crypto for mobile & edge: against harvest-now-decrypt-later, encryption is the urgent half) · NIST CSWP 39 (crypto agility: algorithm identifiers make swaps easier; signatures bound to long-lived identity are the hardest to rotate). Honesty note: the multi-algorithm envelope header is planned; today the version byte fixes the whole suite.

Latency

Post-quantum costs bytes, not time.

Proof

~2 s on GPU

STARK proven in an attested enclave. ~25 s on CPU, ~2 s on GPU — hardware sets the time.

Verifier vote

~1–2 s

Verifier nodes check the proof off-chain and vote; the chain counts votes, never sees the proof.

Settlement

< 1 s

One Solana slot carries hashes and votes; Alpenglow finality, live on mainnet since Oct 2026.

On-chain: 32-byte hashes

  • No proof, ciphertext or signature touches the chain — ~1 KB per transfer, whatever the prover.
  • 1,088 B note ciphertext (vs 32 B X25519), off-chain.
  • ML-DSA-65 sig (3,309 B), ~0.6 MB proof: off-chain.

Full circle with Bunker Mode

  • Vitalik’s ask: keep encrypted notes off-chain. Sombra already does — only the hash is posted.
  • Faster hardware cuts the time; the on-chain bytes stay the same.
Measurement honesty — the ~1.8 s is the GPU proof spend inside the SEV-SNP confidential VM (RTX PRO 6000, devnet, a handful of proofs, proving only; excludes queue and network). ~24 s on the host CPU; ~55 s in the CPU-only CVM. The succinct receipt is ~586 KB. The ~1–2 s verifier vote is the team’s estimate — not yet benchmarked. Private actions · worked example

A private swap, step by step.

Design partners open

Your protocol changes nothing — SPL in, SPL out. No contract ever owns a shielded note.

A private action is a private contract call: the user’s shielded funds drive a public protocol action, and the result returns as a shielded note. Flow: the wallet builds a sealed intent → the relayer submits it and pays fees/rent with an ephemeral key, so the user’s wallet never appears → the prover in an attested TEE produces the STARK → verifier nodes check it off-chain and vote → the program settles the public leg (planned: a single allowlisted call into Jupiter) → finalize appends new note commitments → the wallet finds and decrypts its new note. If the action is rejected or times out, it is cancelled; no nullifiers are created, so the user’s notes stay spendable (a full refund). HONESTY: the swap action is phase 2 — the program already reserves the swap fields but rejects them today. Do not claim batching/aggregation. Swaps are the first planned action kind; staking/lending/perps are design-partner use cases. Status: design partners open. Amounts become public wherever value crosses the private→public boundary (the public leg) — only identity/linkage stays hidden there.
